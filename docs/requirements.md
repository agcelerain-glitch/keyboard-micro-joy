# キーボード反応 & 一問一答タイピングアプリ — 要件定義書

バージョン: 1.0  
作成日: 2026-08-11  
ステータス: MVP Web版（開発者動作確認用デモ）

---

## 1. プロジェクト概要

### 目的
AIへのプロンプト指示後の長考時間を有効活用するための、単機能・単一用途の軽量Webアプリ。

### 2つの使用シーン
| シーン | 使用するモード |
|---|---|
| AI長考中（タイピング練習） | 一問一答タイピングモード（500×500px） |
| プロンプト入力・通常作業中 | キーボード反応モード（200×200px） |

### MVPの位置づけ
- **開発者動作確認用デモ版**。一般配布前の内部検証用。
- Webブラウザのタブがフォーカスされている時のみキーイベントを取得する（バックグラウンド反応は不要）。
- デプロイ: Vercel（GitHub連携）

### 将来構想
- Tauri によるデスクトップアプリ化（Windows / Mac）
- バックグラウンド常時キー反応はTauri化で実現

## 2. コア機能

### 2.1. キーボード反応モード（Keyboard Overlay Mode）

**目標サイズ:** 200 × 200 px

**機能:**
- `keydown` / `keyup` イベントをリアルタイム取得（ブラウザフォーカス時のみ）
- 入力されたキーに応じて、Bongo Cat の左腕 or 右腕がリアルタイムで切り替わる
  - キーボード左半分 → 左腕アニメーション
  - キーボード右半分 → 右腕アニメーション
- 選択中のキーボードレイアウト上で、押されたキーをハイライト表示

**ウィンドウサイズ補助:**
- コンポーネント自体を200×200pxの固定ボックスで囲んで表示（型紙として機能）
- 現在のViewportサイズ（px）を画面右下に常時表示
- ユーザーが手動でブラウザウィンドウを調整し、ボックスにぴったり合わせることで目標サイズを確認できる

**キャラクター画像（Web版）:**
- `front/public/` 配下の固定パスを参照（例: `front/public/cat.png`, `front/public/paw-left.png`, `front/public/paw-right.png`）
- 参考: `other/bongo.cat-master` の画像素材・CSS sprite方式をベースに自作実装
- ユーザー独自画像の差し替えはTauri版で設定ファイル方式により対応（Web版ではfixedパス）

### 2.2. 一問一答タイピングモード（Typing QA Mode）

**目標サイズ:** 500 × 500 px

**機能:**
- 問題文字列を画面に表示
- キー入力をリアルタイム受付。**正解キーが押された時のみ次の文字へ進む**（間違いは無視して待機）
- 入力済みの文字を塗りつぶし表示（残り文字が分かるUI）
- 全文字入力完了 → 自動で次の問題へ
- `Enter` キー → 現在の問題をスキップして次問題へ
- **ミスカウントは記録しない**（正解した文字数のみカウント）

**問題データ:**
- `front/public/data/questions.json` に格納
- 英単語・短文（日本語含む可能性あり）
- 問題はランダム順で出題

**データ将来移行ガイドライン:**

| ステージ | 方式 | 移行トリガー |
|---|---|---|
| Stage 1（現在） | `front/public/data/questions.json` 静的ファイル | — |
| Stage 2（Web版ユーザー編集） | LocalStorage保存 + UIでインポート/エクスポート | 「問題を自分で追加・編集したい」と思ったとき |
| Stage 3（Tauri版） | Tauri fs API + 設定ファイルで任意パス指定 | Tauri化のタイミング |

## 3. モード切り替え

- **ショートカットキー:** `Ctrl + Alt + M`（Web版・Tauri版共通）
- **トグルボタン:** 画面上にも切り替えボタンを設置
- モード切り替え時にウィンドウの固定ボックスサイズが変化（200↔500px）

---

## 4. キーボードレイアウト

### 設計方針
- 問題文字列（例: `"apple"`）は文字データとして独立管理
- 文字 → 物理キー（例: `"a"` → `KeyA`）→ レイアウト上の位置、という2段階マッピング
- これにより問題データとレイアウトが疎結合になり、問題の追加・管理が容易

### 実装するレイアウト（MVP時点）
| レイアウト | ファイル |
|---|---|
| US配列（英字） | `src/data/layouts/us.ts` |
| JIS配列（日本語） | `src/data/layouts/jis.ts` |

- MVPから2種類実装してバグを早期発見する方針
- 共通のレイアウト型（TypeScript interface）を定義し、両ファイルで継承

---

## 5. UI / UX 要件

- **デザイン方針:** シンプル・軽量最優先。複雑なCSSアニメーションは使わない。
- **キャラクターアニメーション:** CSS クラスの切り替えによる画像スワップ方式（canvas不使用）
- **レスポンシブ:** 固定ボックスサイズ（200px / 500px）はFlexboxで中央配置。ボックス外は背景色。
- **Viewportインジケーター:** 右下にウィンドウサイズ（px）をリアルタイム表示

---

## 6. 技術スタック（MVP）

| カテゴリ | 採用技術 |
|---|---|
| フレームワーク | React + TypeScript |
| ビルドツール | Vite |
| スタイリング | CSS Modules（または Tailwind CSS） |
| 状態管理 | React useState / useReducer |
| ホスティング | Vercel（GitHub連携） |
| パッケージマネージャー | npm（または pnpm） |

### 技術選定の理由
- Vite + React + TypeScript は Tauri との親和性が最も高い
- React hooks でキー入力イベント・モード状態管理が整理しやすい

## 8. 開発ステップ（実装順序）

1. Vite + React + TypeScript でプロジェクト雛形作成、Vercel デプロイ可能状態にする
2. モード切り替えUI（`Ctrl+Alt+M` + トグルボタン）と固定ボックス表示を実装
3. US配列レイアウト定義 + `useKeyboard` hook 実装
4. キーボード反応モード: Bongo Cat 表示 + 腕の左右切り替えアニメーション
5. JIS配列レイアウト定義 + レイアウト切り替え機能実装
6. タイピングモード: 問題表示・入力判定・塗りつぶしUI・Enter スキップ実装
7. 問題データ JSON 作成・ランダム出題実装
8. Viewportサイズインジケーター実装
9. 全体動作確認・デプロイ
